## The theorem

```lean
theorem GemJoin.Ilk.ilk_correct (f cA gbh blocks σ σ₀ a s o gp h d bvh) :
  ∃ cA' g' A', Ξ (f + 79) cA gbh blocks σ σ₀ G0 default (env a s o gp h d bvh)
    = .ok (.success (cA', σ, g', A') (UInt256.toByteArray (slot σ a ⟨2⟩)))
```
`env` = calldata `0xc5ce281e`, call value 0, `perm = true`, code = GemJoin runtime, every other
field quantified. `slot σ a 2` = what EVMYulLean's `SLOAD` reads. Cell-by-cell mapping to the
K claim and the narrowings: `phi_delta.md` (new φ version; H must re-sign).

Proof structure (`GemJoin/Ilk.lean`):
- `xi` (kernel `Eq.refl`): one unfolding of `Ξ` into `X` + result packaging.
- `GemJoin.DJ.D_J_runtime`: `D_J runtime 0` = 59-entry literal table (1596 scan steps,
  64 `decide +kernel` chunks in `GemJoin/JumpDest/Chunks0..3`, glued by Lean lemmas).
- `run` (kernel `Eq.refl`): all 77 instructions of `X`, with the account map, addresses and
  storage word symbolic, end in `success` with output `toByteArray (slot σ a 2)` and account
  map `σ`.
- `kernel_theorem` (`GemJoin/KernelRfl.lean`): adds a theorem with proof `Eq.refl` via
  `addDecl`, so only the kernel judges it; no axiom added (tested: rejects `n + 2 = n + 3`).

Negative controls (`controls/IlkMutants.lean`, run 2026-10-29): the kernel **rejects**
`run` with slot 3 instead of 2, with the `gem()` selector `0x7bd2bea7`, and with call value 1;
it accepts the unmutated control. So the statement is not vacuous: it pins slot, selector
and the non-payable check.

Assumptions for T̂:

- **A_sem_DJ** — patched `D_J_aux` (fuel `c.size + 1`) = upstream `partial def D_J_aux`.
  Argument: every recursive call needs `i < c.size` and advances `i` by ≤ 33 without
  wrapping, so the fuel is never exhausted while `c.size + 33 < 2^256`. Not provable (a
  `partial def` has no equations). Empirical (compiled `#eval`, not a verdict): the upstream
  body, copied verbatim as a `partial def`, and patched `D_J` give the same 59 entries
  `[16, 113, 169, …, 3354]` on the GemJoin runtime, equal to `GemJoin.DJ.table` and to an
  independent Python scan (all stop at 3470). WETH9/Vat: not checked, no runtime bytecode
  for them on the VM. **risk_if_false:** `JUMP`/`JUMPI` destinations accepted or rejected
  differently from upstream; a proof could certify a run upstream rejects, or the reverse.
- **A_sem_zeroes** — `zeroes n = ⟨Array.replicate n 0⟩` matches C `memset_zero` as used by
  compiled upstream. Equal for `n < 2^64`; compiled upstream passes `n mod 2^64` beyond that
  (unreachable under any gas schedule). **risk_if_false:** wrong memory contents or sizes after
  `MSTORE`, padded reads, `RETURN`.
- Kernel vs compiled code: the kernel uses the Lean bodies; the `@[extern "memset_zero"]` is
  removed, so `#eval` no longer calls C either. Delivered proofs must not use `native_decide`,
  `Lean.ofReduceBool` or `Lean.trustCompiler`; D7's whitelist rejects them anyway, and none
  is used. Every `#eval` in this work is a sanity check, never a verdict.

## Dead ends (kept for the record)

- `decide +kernel` over the whole jump-table scan: OOM-killed at 11 GB.
- One equation `X (f+72) s0 = X (f+1) s1` for 71 instructions, and also 5 chunks of ≤ 15:
  `(kernel) deep recursion` (with `--tstack=4000000`: deterministic timeout after 426 s,
  13.6 GB), although every field of `s1` matched individually. X-vs-X equations make the
  kernel unfold both sides in lockstep. Fixed by patch 0005 + one whole-run evaluation in
  `match … with` form (`run`).
